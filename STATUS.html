Hunting Distant Planets: What Our Code Can Do So Far

NASA's TESS telescope finds planets by watching for tiny blinks — a planet passing in front of its star blocks a little starlight. Our code tackles the hard case: planets so far out that TESS only catches them blinking once, years apart. Below is what the code can already do, shown with a real run on practice data — plus an honest list of what it can't do yet.

24 / 24 self-checks passing practice data only — no real discoveries yet 3 Sep 2026

The problem in 30 seconds

TESS stares at each patch of sky for about 27 days at a time. A planet that orbits in a week blinks over and over — easy to spot. But a planet that takes months or years to orbit might blink just once while TESS is watching. One lonely blink with no pattern looks a lot like camera noise, a flickering star, or two stars eclipsing each other. Useless on its own.

Here's the opportunity: TESS keeps revisiting the same stars years later. If that same star blinks again, the two blinks together are powerful evidence — if you can prove both blinks came from the same planet. That's exactly the question our code answers.

What the code can do right now

We ran the code on a practice star with three recorded blinks. Two were designed to be from the same (imaginary) planet, 900 days apart; the third is an impostor. Here's what happened:

Step 1 — Match the blinks

The code compares every pair of blinks on four clues: how deep the blink is, how long it lasts, the shape of the dip, and whether the timing makes sense. Results:

PairVerdictWhy, in plain words
Blink A + Blink BMATCHSame depth, same length, same dip shape — almost certainly the same planet.
Blink A + Blink Cno matchC is 5× deeper, twice as long, and V-shaped instead of U-shaped. Different object.
Blink C + Blink Bno matchSame mismatches — plus only 5 days apart, too close to allow any long orbit.

Step 2 — Figure out the orbit

Two blinks 900 days apart could mean an orbit of 900 days (one lap between blinks), 450 days (two laps), 300 days (three laps), and so on — 33 possibilities in total. The code then plays detective with TESS's actual observing calendar: for each guess, it asks "would TESS have seen a third blink by now?" If yes, but no blink was recorded, that guess is crossed off.

Kept 11 possibilities — including the true answer, a 300-day orbit.

Crossed off 22 — every one of them predicted a blink during a stretch when TESS was definitely watching and saw nothing (for example, the 450-day guess demands a blink at day 1795, right in the middle of an observed stretch — absent, so it's out).

That's the whole trick of the project: turn one mystery blink into a short, ranked list of suspect orbits, each backed by a reason a human can check.

Step 3 — Prove it plays fair

Science only counts if you can't peek at the answers. The code is fenced off from newer observations by design, and this run certifies it touched zero sealed data. It also double-checks that identical blinks score identically no matter when they happened — a rounding bug that once made the score depend on the calendar date is fixed and pinned by a test.

What the code can NOT do yet (honest list)

  • Find real new planets. Everything so far runs on practice data we invented.
  • Spot blinks by itself. It compares blinks; it doesn't find them in raw telescope recordings yet.
  • Rule out impostors fully. Telling planets apart from eclipsing binary stars needs extra checks not yet built.
  • Use AI. The current matcher is hand-written rules. The learning experiment hasn't started.
